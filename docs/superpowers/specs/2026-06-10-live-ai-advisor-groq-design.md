# Design — Live AI Advisor (Groq)

**Date:** 2026-06-10
**Status:** Approved (ready for implementation plan)
**Scope:** Second backend sub-project. Replace the mocked rule-based assistant
with a real Groq-powered conversational advisor. Streaming, agentic tool-calling,
working voice input, chat persistence, and auth are **out of scope** (later
add-ons).

---

## 1. Goal & success criteria

The site is positioned as "AI-powered", but the floating **AI Advisor**
(`src/components/ai/ai-assistant.tsx`) currently runs a hand-written
`getResponse()` that pattern-matches keywords and returns canned text. Make it a
genuine LLM conversation, grounded in BlueRoute's real offering.

**Success looks like:** a visitor opens the advisor, asks a free-form logistics
question, and gets a relevant, on-brand answer generated by Groq — multi-turn,
with the existing call-to-action buttons still appearing where useful. Abuse is
lightly guarded, and failures degrade to a friendly fallback.

**Decisions (from brainstorming):**
- **Prompt-only** (no agentic tool-calling) — a rich grounded system prompt; the
  advisor routes users to `/quote`, `/tracking`, etc. rather than computing
  binding figures itself.
- **Non-streaming** — typing indicator, then the full reply appears.
- **Light abuse guard** — message-length cap + per-IP rate limit, no login.

---

## 2. Architecture

**Pattern: a Next.js Server Action `askAdvisor(messages)`** (App Router, same
pattern as the forms sub-project — verified against
`node_modules/next/dist/docs/01-app/01-getting-started/07-mutating-data.md`).
Server Actions accept serializable arguments, so the client passes the
conversation history array directly. The action injects the system prompt, calls
Groq once (non-streaming), and returns the reply. Secrets (`GROQ_API_KEY`) stay
server-side.

**Rejected alternatives:** a streaming Route Handler (not needed — non-streaming
was chosen) and the Vercel AI SDK (the project already has `groq-sdk`; no new
dependency).

### Data flow

```
Chat panel (client) ──askAdvisor(history)──▶ Server Action
   buildSystemPrompt() from live SERVICES + PORTS data
   validate input + per-IP rate limit
   Groq chat completion (non-streaming, model from env)
   extractCta() pulls an optional CTA directive out of the reply
 ◀── { ok: true, content, cta? } | { ok: false, error }
Panel appends an assistant bubble (typing indicator while awaiting).
```

## 3. Files

**New:**
- `src/lib/ai/types.ts` — `AdvisorMessage = { role: "user" | "assistant"; content: string }`,
  and `AdvisorResult = { ok: true; content: string; cta?: Cta } | { ok: false; error: string }`
  where `Cta = { label: string; href: string }`.
- `src/lib/ai/system-prompt.ts` — `buildSystemPrompt()` assembles persona,
  capabilities, and **guardrails** from the live `SERVICES` (services-data) and
  `PORTS` (quote-data) so the prompt never drifts from the site. Guardrails:
  stay on logistics topics; never invent binding prices/ETAs (direct to
  `/quote`); no legal/financial guarantees; concise, premium tone; may end a
  reply with one optional CTA directive line (see `cta.ts`).
- `src/lib/ai/cta.ts` — `extractCta(raw): { content: string; cta?: Cta }`. The
  model may append a final line `CTA: /path | Label`; this extracts it into a
  structured `cta`, strips it from the visible text, and **only** accepts known
  internal routes: `/quote`, `/tracking`, `/warehousing`, `/services`,
  `/contact`. Unknown/malformed directives are dropped (text kept clean).
- `src/lib/ai/rate-limit.ts` — `checkRateLimit(key, now): boolean`, an in-memory
  sliding-window limiter (default **8 messages / 60s** per key). No DB; state is
  per-server-instance and resets on redeploy — acceptable for a light guard.
- `src/lib/ai/groq.ts` — server-only Groq client (`import "server-only"`, lazy
  singleton from `GROQ_API_KEY`) plus `chat(messages): Promise<string>` doing a
  non-streaming completion. Model from `GROQ_MODEL`, default
  `llama-3.3-70b-versatile`.
- `src/app/actions/advisor.ts` — `'use server'` `askAdvisor(messages: AdvisorMessage[]): Promise<AdvisorResult>`.
  Caps each message (~2000 chars) and history (~last 12 turns), rate-limits by
  client IP (from `headers()` `x-forwarded-for`), calls `groq.chat`, runs
  `extractCta`, returns the result.

**Modified:**
- `src/components/ai/ai-assistant.tsx` — replace the mock `getResponse` +
  `setTimeout` with an `askAdvisor` call that sends the real history (mapped to
  `AdvisorMessage[]`). Keep the typing indicator, quick prompts, and CTA
  rendering. **Drop the fake "thinking steps"** (`Msg.steps`) — there is no real
  reasoning trace in prompt-only mode. On `{ ok: false }` or a thrown error,
  append a friendly fallback assistant bubble.
- `.env.local` — add `GROQ_API_KEY` (and optional `GROQ_MODEL`). Timi pastes the
  key; setup is guided.

## 4. System prompt (content outline)

Built at request time from real data so it stays accurate:
- **Identity:** "You are the BlueRoute AI Advisor, the assistant for Blue Route
  Logistics, a premium AI-driven global freight forwarder."
- **Capabilities:** quoting, shipment tracking, risk analysis, multi-leg route
  planning, warehouse matching.
- **Grounding:** the list of services (names + one-line value from `SERVICES`)
  and the set of served ports (city/country/code from `PORTS`).
- **Guardrails:** concise and helpful; logistics scope only; for binding quotes
  or live tracking, direct the user to the tools (`/quote`, `/tracking`) rather
  than inventing exact numbers; no legal/customs/financial guarantees; optionally
  finish with a single `CTA: /path | Label` line when an action would help.

---

## 5. Error handling

- **Empty or oversized** message → friendly inline rejection, no Groq call.
- **Rate-limited** → `{ ok: false, error: "You're sending messages quickly — give it a few seconds." }`.
- **Missing `GROQ_API_KEY` / Groq API error / timeout** → caught and logged
  server-side; returns `{ ok: false, error: "The advisor is briefly unavailable — please try again, or use the quote and tracking tools." }`.
- The client renders any `{ ok: false }` error as a normal assistant bubble so
  the conversation never appears broken.

## 6. Testing

Uses the existing **Vitest** setup.

- **Unit `system-prompt.ts`:** output contains the company name, at least one
  real service name, and the no-binding-quotes guardrail phrasing.
- **Unit `cta.ts`:** parses a valid `CTA: /quote | Get a quote` line (strips it
  from content), rejects an unknown path (e.g. `/evil`), and returns content
  unchanged when there is no directive.
- **Unit `rate-limit.ts`:** allows the first N within the window, blocks N+1,
  and allows again after the window elapses (time injected, not real clock).
- **Integration `advisor.ts` (mocked):** Groq client and `next/headers` mocked —
  asserts a normal call returns `{ ok: true }` with content (and a `cta` when the
  mock reply includes a directive), the rate-limit path returns the guard error,
  oversized/empty input is rejected without calling Groq, and a thrown Groq error
  returns the fallback error.
- **Manual:** open the advisor on `npm run dev`, ask several real questions
  (route planning, warehouse, "what is door-to-door?"), confirm coherent on-brand
  answers and that CTAs appear; send messages rapidly to trigger the guard.

Implementation follows TDD (tests before implementation).

## 7. Setup (Timi performs, guided)

1. Create a Groq API key at https://console.groq.com (free tier is fine).
2. Add to `C:\Users\Timel\Desktop\BlueRoute\.env.local`:
   ```
   GROQ_API_KEY=gsk_your_key_here
   # optional, defaults to llama-3.3-70b-versatile
   # GROQ_MODEL=llama-3.3-70b-versatile
   ```
3. Restart `npm run dev` so the key loads.

If `llama-3.3-70b-versatile` is ever retired on Groq, set `GROQ_MODEL` to a
current model from the Groq console — no code change needed.
